## H12 hardening

- `fmt_price` and `fmt_change` print `--` for NaN and infinity, so `board_text` does too. Test
  `a_non_finite_number_prints_as_dashes`, seen failing first.
- `Layout::y_of(NaN)` is the middle of the plot (the old value, the bottom edge, is outside the
  plot because `Rect::contains` excludes `bottom`); an infinite price is held 2^24 px away so the
  sum cannot overflow. Test `y_of_a_non_finite_price_stays_inside_the_plot`, seen failing first.
- `chartview::newest_that_fit` drops the oldest candles when even one-pixel slots are fewer than
  the candles; used by the panel and by `shot.rs`. Test `no_candle_lies_past_the_plots_right_edge`
  (120 hourly bars, plot 40 to 250 px, 96 to 192 DPI), seen failing with the function made a no-op.
- The update request's `User-Agent` is `update::USER_AGENT` = `MH-Ticker`; test
  `the_update_request_sends_an_app_name_only`. The other requests (CNBC) keep the browser string:
  decision, because CNBC is the host most likely to refuse an unknown agent and nothing here can
  test that. Unverified live.
- Cooldowns: `alerts::cooled(now, last, cooldown)`. A wall clock set back made `now - last`
  negative and silenced the alert until the clock caught up; now it reads as cooled and the next
  fire writes a fresh stamp. Decision: this is a guard on the wall clock, not a monotonic clock,
  because `last` is persisted and the staleness test compares quote stamps with the wall clock.
  A jump costs at most one early fire. Test `a_clock_set_back_does_not_silence_an_alert`, seen failing first.

## H10 typed levels

- `alerts::parse_level_why`: the first group of commas is one to three digits and each later group
  exactly three. `4200,5`, `4,20`, `1,2345`, `,500` are refused with a reason; `4,200.50` is
  4200.50. The old test accepted `4,20,0` as 4200; that row contradicts the rule and was removed
  from the accepting list (it is in the refused list of the new test).
- `alerts::far_level_question`: asked when the level is MORE than 20 % from the fresh price
  (exactly 20 % is not asked; decision, the brief says "more than"). It echoes the level and the
  price in the symbol's digits. Test seen failing first: `a_comma_that_does_not_group...` (old
  code read `4200,5` as 42,005).
- The echo is carried by the far-level question; a level within 20 % is set silently as before.

## H13 kept settings

- `config::load_or_keep` renames a settings file that is not UTF-8 or does not parse to the first free
  `settings.bad.json`, `settings.bad-2.json`, ... and writes the defaults at the path. The bytes are
  moved, never rewritten. `config::load()` records the kept file NAME (not the folder, which carries
  the user name) in `KEPT_AS`; the menu shows a greyed line `Settings were unreadable; kept as <name>,
  defaults loaded` (id 5406). If the rename fails the file stays and start-up reports the error as
  before. The old `load_from` and its test (`invalid_config_file_is_not_replaced_or_migrated`) are untouched.
- `config::load_readonly()` for `--probe`: never writes or moves anything.
- Test `a_config_that_will_not_parse_is_kept_and_defaults_load` (temp folder; bytes with an invalid
  UTF-8 byte and a webhook-looking string; second failure keeps both). The old behaviour (an error
  box, no start) is what `invalid_config_file_is_not_replaced_or_migrated` still pins for `load_from`.
- Unverified: the menu line on a real desktop.

## H5 data meter

- `src/meter.rs` (pure, std only, added to `scripts/check-state-linux.sh`): 60 one-minute slots plus a
  total, 484 bytes (test asserts <= 512). A slot carries its minute number, so no timer sweeps it;
  an hour-old slot is ignored by `last_hour` and overwritten on the next write. Tests: hour
  roll-over (59 vs 60 minutes), idle hour, clock set back, the menu line, size formatting.
- Wiring: `source::Counted` wraps the reader of every response body (quotes, bars and range files via
  `get_within`, the alternate-source GET, lookup, release check) and adds its byte count to
  `source::METER` once, on drop. Webhook POST bodies are added by length. No new HTTP call, no thread, no timer.
  `get_within` now calls `serde_json::from_reader` on the counted reader, which is exactly what
  `into_json` did; its error text is kept ("Failed to read JSON: ...").
- Menu line, greyed, id 5407, above the version line.
- Decision: bytes are counted as read, after the library has unpacked gzip. On the wire the number is
  lower for compressed answers. Request headers are not counted. Unverified: how the figure compares with
  a real capture, and the line on a real desktop.

## H11 local time per instant

- `chartview::Zone { before, change_at, after }`: a clock that changes at most once inside a series.
  `Zone::spanning(first, last, offset_at)` asks the offset at both ends (two calls) and bisects to the
  minute only if they differ. `fold`, `fitted`, `fitted_to`, `readout_with` take `impl Into<Zone>` (an
  `i32` still works, so every old call and test is unchanged). A bar is read on the clock in force at
  its own instant; a bucket starts on the clock of the bar that opened it. The panel's tick loop
  (`key`, `local_day`, `date_label`, `clock`) asks `zone.at(tb)` per bar. `Chart::tz_offset_s` became
  `Chart::zone`. Daily series keep the fixed +12 h exchange-date clock (`date_zone_of`).
- ui: `local_offset_at(t)` = `FileTimeToSystemTime` + `SystemTimeToTzSpecificLocalTime`, offset =
  local reading minus UTC reading (`chartview::civil_secs`). Falls back to the offset now.
- Alerts: `local_hhmm(offset_at, now, at)` and `entry_line(e, offset_at, now)` read each time on its own
  offset. The old tests keep their expectations through a `clock_at` helper (a constant offset).
- Tests: `a_fold_across_a_clock_change_cuts_each_day_on_its_own_local_midnight` (the same test shows
  the one-offset fold putting a post-change candle off its midnight, i.e. the old failure),
  `zone_spanning_finds_the_change_to_the_minute`, `a_time_across_a_clock_change_shows_the_hour_it_had`
  (the mute label and the Recent lines). The one-offset result being wrong is asserted inside the fold test.
- Unverified: the real `SystemTimeToTzSpecificLocalTime` across a real change (Wine's zone is UTC,
  so the Wine test only checks it agrees with the offset now). A zone that changes twice inside one
  series (a 5Y intraday window does not exist) is read as one change.

## H4 the chart says when it is suspect

- `ranges::stamps_on_day_boundary(stamps)`: every stamp's UTC time of day is a whole quarter hour
  (30 s tolerance, the f32 offsets are 16 s coarse five years out) and all agree to within an hour (a
  clock change). `Series::check()` (daily or longer only) gives `Check { dates_off }`; nothing is stored.
  `ranges::age_label(now, fetched, ttl, tz)` gives `as of 14:05` (with a date from 0.9 day on) once
  the series is past its time to live PLUS `STALE_GRACE_S` (30 s, the retry period). Decision: the grace
  stops the note flashing during every normal refresh (a request in flight at the ttl); a refresh that
  has failed shows it. `Series::note` joins the two with a middle dot.
- Shown on the header's second line (the legend line) in the accent colour, only while no candle is
  hovered, only if it fits left of the tabs. The legend replaces it under the pointer. 1D has no
  note (the board's own day, not a cached series).
- Repaint: a hover change names the whole pane (`was.aim != now.aim` adds `pane`), which holds the
  line. Test: `a_hover_change_repaints_inside_the_rectangle_it_names` now also runs with a note;
  `the_chart_note_shows_until_a_candle_is_hovered` checks it is drawn on that line and the legend wins.

## H1 and H3 the judging probe and --dump

- `src/probe.rs` (pure; uses `serde_json` and the pure `ranges`, `update`, `chartview`; added to the
  Linux harness): `judge(&Bodies) -> Vec<Finding>`, `render`, `exit_code`, `dump_dir`, `dump_files`,
  `write_dump`. `parse_time` moved here from `source.rs` (re-exported there, tests unchanged).
- Findings and their ids: `quote-fields`, `unknown-symbol`, `time-spelling`, `bar-start`,
  `daily-boundary`, `volume`, `release-tag`, plus `unread-fields` (NOTE) and `*-request` (WARN when an
  answer did not come or is not JSON). Verdicts are PASS, WARN or NOTE. A NOTE means "not testable in
  these answers" and never fails the run; it is used where an assumption cannot be seen while the market
  is closed (`bar-start`), where no daily file came back, and for the unread field names. This is a
  third word beside the two the brief named; the alternative was a PASS that tested nothing.
- `bar-start` compares the quote's trade time with the last 1D bar of the same symbol, only when that
  bar closes at the quote's price: inside the bar means start stamps (PASS), before its stamp means
  end stamps (WARN), a stamp in the future is a WARN, a closed market is a NOTE.
- `volume` WARNs when no bar in any file carries a volume. An index row (no volume at all) will WARN;
  that is true (the strip will not draw) but it is the reason a WARN does not always mean breakage.
- Every text in a finding is made of symbols, numbers and cleaned field names (`clean`): no body, URL
  or network error text. Test `nothing_from_the_network_is_printed_beyond_names_and_numbers`.
- Fixtures are hand-written JSON built in the tests (`good()` and one variation per warning); each
  named assumption has a passing and a warning test. No live request was made; CNBC was unreachable.
- `source::collect_bodies` fetches: all shown symbols' quotes (one request), one unknown symbol, the 1D
  file of the first `day_rows` rows, the four range files of the first row, the release answer. `--probe`
  asks the 1D file of every row (as before); the diagnostics report (H2) only the first row, to bound
  the wire cost of a click (decision). `source::probe` still prints the old overview, then the findings,
  and returns whether any WARN; `launch` exits with 1 on one. A bad `--dump` or a `--dump` without
  `--probe` exits with 2 and a sentence. `--probe` reads the settings with `config::load_readonly`, so
  it never writes the config (the old `load` could write defaults or migrate).
- `--dump <dir>`: `quotes.json`, `quote-unknown.json`, `day-NN-<symbol>.json`, `range-<file>`,
  `release.json`; failed answers have no file; the folder is created if missing. Test with a temp folder:
  the file list is exactly those names, none is a settings or webhook file.
- Unverified: all of it against the live services; the wording of a real unknown-symbol answer; that
  every real shown symbol is echoed with the same spelling in `symbol` (the judge matches exactly, as
  `resolve` does).
