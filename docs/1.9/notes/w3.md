# W3 note: Twenty-four symbols (writer)

Picture: [w3-5y.png](w3-5y.png) (5Y pane, alert levels, W1's `as of` and `check dates` note, L1's header
change and high/low marks; looked at, no collisions). New still: `shots/w3-strip-24-pinned-6.png` (24
symbols, 6 pinned: only the six are laid out). Both come from `examples/w3.rs`
(`cargo run --release --example w3 --features shots -- <dir>`). The 36 catalogue stills are identical.

## What was built, per item

**L3.** `ranges::MAX_SERIES` is 48. Added a second ceiling, `MAX_CACHE_BYTES` (2 MB of bar bytes), because
the parser allows 4,000 bars a series (96 KB) and 48 of those would be 4.6 MB; at the planned size
(`FULL_SERIES_BARS` = 1,100 bars, 24 bytes each) 48 series are 1,267,200 bytes, under 1.3 MB, which a
test states. Only the on-screen key is ever passed to `Book::want`, so nothing off screen is due (test).
The old "13th evicts" test now reads from `MAX_SERIES` (same property, new cap).

**B11a.** `Config::chart_range` (absent = 1D; 1D is never written). `Range::from_saved` and `to_saved`.
The range is no longer reset when the chart closes, is read at start-up (Ultra) and saved on a tab click
(outside `with_ui`).

**D5.** `config::order_by(cfg, moves, OrderKey::{DayMove, Name, Default})`. A one-shot rewrite through the
same catalogue permutation P5 uses (`move_shown` now calls `apply_order`), so hidden symbols keep their
slots. Day move sorts by absolute change, biggest first; a row with no fresh quote keeps its relative place
at the end; the sort is stable. Symbols menu > *Order the cards (once)*, both builds.

**J3.** `rename`, `reset_name`, `derived_label`, `set_digits`, `auto_digits`, `clean_label`. A label follows
P6's rules (8 characters, unique ignoring case, a number on a collision; hidden catalogue labels and other
symbols' alert labels count as taken). Rename moves the row, the catalogue entry, the alerts and the lock.
Decimals: Auto (a default symbol's own count, else from its price), 0 to 6. Card menu, both builds.
Rows are rebuilt from the catalogue by `toggle` and every move, so a label or a digit count has to be set
on both; the code does.
Found while doing it: `Board::set_rows` and `History::align` matched a row by label and symbol, so a rename
would have dropped the quote, the bars and the sparkline until the next fetch. They now match by symbol.

**J1.** `Row::strip` (absent = pinned; only `false` is written). `pins.rs` (pure), `config::strip_rows`,
`set_pin`, `pin_all`, `normalize_pins`, `keys::remap_slots`. The strip layout filters the cards to the
pinned ones and renumbers the click rectangles to card indexes, so a click finds the right card. The last
pinned row cannot be unpinned; hiding it, a restore or a hand-edited file with none pinned pins every row
again. Card menu *Pin to strip* / *Unpin from strip* and Symbols > *Show all on strip*, both builds. The
panel shows no pin mark on a card (only the menu says): open.

**J2.** `undo.rs` (one snapshot, `put`, `take`, `drop_rows`), `config::Snapshot`, `Config::snapshot_rows`,
`snapshot_alerts`, `restore`. Decision that differs from the brief's wording: the snapshot is the cards
(rows and catalogue) for remove, move, sort and pin, and the alerts for an alert clear, not the whole
config. The webhook is in neither, so no undo can restore it, and an undo does not roll back unrelated
settings changed since (opacity, theme, a new alert). Cards go back whole; alerts are merged back (an alert
set since for the same label stays as it is now). A cards snapshot is dropped by `apply_rows` when the cards
change any other way (add, show, rename, decimals, forget, reset), because restoring it would undo that too.
Menu line *Undo the last removal* (grey when nothing is held), both builds; Ctrl+Z in the panel on Ultra
only (Classic keeps 1.8's keys). Hiding a symbol from the Symbols menu or the picker counts as a removal.

**J6.** `find.rs` (`find`: label prefix, label substring, name substring, first in order; `scroll_to_show`,
which `panel::reveal` now calls, so P5's reveal tests cover it too). `/` (the character, through `WM_CHAR`)
opens a prompt on Ultra; Esc, empty text or no match changes nothing. Home and End lock the first and last
card on Ultra when the panel has cards, and scroll to it; on Classic they keep paging the body, as in 1.8.

**L1.** `chartview::range_change` (last close against the first open; nothing for a zero or non-finite
first open), `range_change_text` (`5Y +182 %`), `extremes`, `place_label` (a label inside the plot clear of
every rectangle it is told to avoid). The header shows the range change instead of the day's change on every
range but 1D (1D is as P2 left it; its still is identical). H and L marks: a small square on the extreme
candle with its price, placed clear of alert level lines and prices, edge-level markers and the last-price
line; a label with no room is left out and the square stays. The picture shows them clear of everything.

## Not verified
- Real key presses and the keyboard focus after the find prompt closes (the prompt is modal and runs outside
  `with_ui`; whether the panel keeps focus is unseen).
- The strip at each placement on a real taskbar with pins (the layout filter is the same code at every
  placement; the pictures are of the 2-row grid only).
- Ctrl+Z and `/` need a real keyboard; `WM_CHAR` arrives only if the message loop translates it (it does).
- Menu entries were not clicked.
- The picture's marks use the synthetic weekly series; a real 5Y file's bar count is unverified (the cache
  arithmetic assumes at most 1,100 bars and has the byte ceiling behind it).
- An alert restored by undo keeps its saved `last` time, which can be older than a fire since; at worst one
  repeat after the cooldown.

## Review
The checker accepted two decisions that differ from the brief, and both are now the behaviour:
- The undo snapshot is narrower than "whole config minus the webhook". It holds the cards (rows and catalogue)
  for a removal, move, sort or pin change, and the alerts for an alert clear. It never holds the webhook, and it
  is dropped when the cards change another way (add, show, rename, decimals, forget, reset).
- Ctrl+Z works on Ultra only. The *Undo the last ...* menu line is on both builds, so Classic has the undo too.

The checker added the `[[example]]` entries for `wide` and `w3` to `Cargo.toml`, which answers the first item
under "Open / for the checker". The checker also regenerated the six `shots/wide-*` stills whose pane header
changed with L1.
