## Architecture

- **Stack:** [inferred] Extend existing Rust 2021/Win32/GDI ticker; use `chrono` plus `chrono-tz` with its compiled IANA database for the four sessions, pin versions and record tzdb version so clean Windows needs no external zoneinfo. Map the Windows dynamic time-zone key to an IANA zone using a pinned CLDR Windows-to-IANA mapping with territory handling; display a clearly unavailable device row if mapping fails. Review dependency licenses and updates. Build Pine Script v6 and MQL5 indicators from the same versioned rules and vectors. No Go runtime is involved; any future Go implementation using `time.LoadLocation` must embed `import _ "time/tzdata"` [measured: brief, [BRIEF.md](/workspace/qol-portfolio/BRIEF.md:100)].
- **Shared definition and modules:** [inferred] A versioned JSON spec is the single source for four ordered IDs, IANA zones (`Australia/Sydney`, `Asia/Tokyo`, `Europe/London`, `America/New_York`), agreed local open/close times, weekdays, overnight semantics, holiday/exception policy and effective range. Generate Rust constants, Pine session strings and MQL5 constants and zone transition tables from it; never edit generated copies by hand. Pin tzdb and record its version and valid years; regeneration, a diff check and golden UTC vectors guard drift. Use half-open intervals [open, close), resolve ambiguous/nonexistent local times by explicit spec policy, and compute the next transition and intersection of London and New York intervals in UTC. Session hours and calendar exceptions require approval before shipping; do not invent them. A broker rule contains configurable UTC offset, eligible reopen days, seasonal rule and overrides with provenance; calculate reopen as an instant and mark unknown when its rule or coverage is unverified. Internal default-preset note: Exness. [measured] Pallas's reported observation is UTC+0 server year-round and daily reopen at 22:00/23:00 server depending on US DST ([BRIEF.md](/workspace/qol-portfolio/BRIEF.md:26)); seasonal mapping, exceptions and changes need independent confirmation [inferred].
- **Modules:** [inferred] About screen showing “Made by Maria”; the ticker feature, shared session engine and platform indicator modules follow.
- **MH Ticker feature:** [inferred] Add a pure session engine, Windows zone adapter and panel section to existing config/UI, independent of quote fetch. Fixed displayed order is Sydney, Tokyo, London, New York and broker server time, followed by exactly one auto-detected Windows device-zone clock; never replace or reorder defaults, even when zones match. Show open/closed, next open/close countdown, overlap state and next broker reopen. Recompute from wall-clock instants after wake, clock or zone changes; refresh on a UI timer, without tying updates to quotes. Keep existing settings and migrate new fields with defaults.
- **Pine indicator:** [measured] Pine scripts cannot access the chart time zone, and the manual recommends a user input to match it; `syminfo.timezone` is the symbol exchange zone, not the chart or device zone. The documented `chart.*` built-ins have no zone ([BRIEF-v5.md](/workspace/qol-portfolio/BRIEF-v5.md:51); [Pine v6 time manual](https://www.tradingview.com/pine-script-docs/concepts/time/)). [inferred] Generate v6 session strings and use `time(timeframe.period, session, IANA_zone)` for bar membership. Append exactly one extra clock using `input.string` with an IANA dropdown, default `syminfo.timezone`, labelled “set to your chart/device zone”; render `timenow` with `str.format_time(..., tz)`. Never claim chart or device auto-detection. Preserve fixed rows and order; calculate overlap and broker reopen from generated rules. Pine updates on chart events, so show last update and historical/realtime limitations; configurable broker offset is an estimate, not a live feed.
- **MT5 indicator:** [inferred] Generate MQL5 constants and bounded IANA transition tables from the pinned tzdb, and evaluate each session's DST from UTC instants in code, including southern-hemisphere transitions; do not infer session DST from broker server time. Use `TimeTradeServer()` and `TimeGMT()` to estimate current server-minus-GMT offset, with an explicit configurable offset override and stale/disconnected and strategy-tester caveats; do not apply today's offset retrospectively to historical bars. Compute countdowns from a UTC clock and the selected broker rule, display data age and unknown if clock/offset is unreliable. Append one device clock using `TimeLocal()` and its offset from `TimeGMT()` for the current device clock where available, visibly label it and show unavailable if it cannot be trusted; keep the four defaults and server clock ordered. MQL5 has no assumed general IANA database: regenerate embedded tables and fail visibly outside their coverage. Verify indicator timer and local-clock behavior on the target terminal before claiming automatic detection.
- **Key platform APIs:** [inferred] Ticker uses Win32 `GetDynamicTimeZoneInformation`, time/setting change notifications, UI timers and its existing `Shell_NotifyIconW`/GDI message loop; confirm Windows-to-IANA mapping and device changes. Pine uses `time()` with session and IANA zone, `input.string`, `timenow`, `str.format_time` and realtime table rendering. MQL5 uses `TimeTradeServer`, `TimeGMT`, local time, `EventSetTimer`/`OnTimer` and chart objects; verify actual clock and tester semantics in integration tests.
- **Data/config:** [inferred] Store ticker broker override, reopen rules, zone-map version and UI preferences in the existing `%LOCALAPPDATA%\MH_Ticker\config.json`; migrate without disturbing quote settings. The spec and pinned tzdb/golden vectors are build inputs; indicators embed generated rules and offer platform inputs, not runtime JSON dependencies. Show source/version/coverage, offset and overrides, and whether broker time is measured or configured. No online data is required for timers.
- **Packaging:** [inferred] Ship the feature in MH Ticker's existing GitHub Releases and installer with uninstaller, then a manually reviewed winget manifest; prepare MSIX for optional Store submission. Distribute Apache-2.0 Pine and MQL5 source boilerplates and spec/vectors as versioned release assets with installation and limitations, rather than treating them as separate Windows installers. Include LICENSE, SPDX headers and `THIRD_PARTY` for third-party code/data, checking tzdb/CLDR and dependency terms. Warn before any future system-setting changes. [measured] The brief supplies, without independent re-verification, that Store certification re-signs MSIX with a Microsoft certificate; EXE/MSI Store submissions must be pre-signed with a trusted certificate and self-signed certificates are rejected ([BRIEF.md](/workspace/qol-portfolio/BRIEF.md:76)). GitHub/winget downloads remain unsigned with SHA256SUMS and “not code-signed yet” until [SignPath Foundation](https://signpath.org/terms) approves. [measured] Ava's supplied terms say apps need verifiable reputation; application is the Manager's call; requirements include 2FA, CI-built binaries, manual release approval, a “Code signing policy” naming authors, reviewers and approvers, privacy statement, uninstaller and warning before system-setting changes; publisher displays “SignPath Foundation” ([BRIEF.md](/workspace/qol-portfolio/BRIEF.md:87)).
- **Tests:** [inferred] Run shared golden vectors through Rust and test harnesses for generated Pine/MQL5 logic, then compare platform output at the same UTC instants: before/at/after opens and closes, overnight/weekend, leap/year rollover, overlap and broker reopen. Cover March US/UK mismatch (about 2–3 weeks), late-October mismatch (about one week), Sydney April and October transitions, Tokyo and UTC conversion, plus offset overrides and verified seasonal reopen examples. Check invalid or expired tables and unknown broker schedules. Test exactly one additional row and fixed order, Pine zone input/default and user changes, Windows device zone changes and failed mapping, sleep/resume and clock changes, config migration, offline quotes, DST and timezone-data version drift. Pine tests must exercise live versus historical bars and missing ticks; MT5 tests must cover disconnects, server/GMT offsets, tester semantics and transition-table boundaries. Run `cargo test`/clippy and Windows tray, DPI, Explorer restart and installer/uninstaller checks. Release-check on clean Windows without Go and compare London/New York against known instants; verify packaged IANA data and device mapping there.
- **Size:** [guess] L: 15–25 developer days and 1,500–2,800 changed LOC across ticker, generators, two indicators and tests, excluding session/broker rule verification and platform review.
