# P3 Everyday: notes for users and reviewers

Branch `wip/p3-everyday`. Applies to both builds (MH Ticker and MH Ticker Ultra). Classic looks and behaves as
before unless you use one of the new menu entries.

## What was built

1. **Start with Windows.** A checkbox in the menu. Ticking it adds a value under
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, named after the profile (`MH_Ticker` or `MH_Ticker_Ultra`),
   holding the quoted path of the running exe. Unticking removes it.
2. **Global hotkey.** A key combination that opens and closes the panel from anywhere.
3. **Refresh now.** Fetches all prices and chart data at once instead of waiting for the next poll.
4. **Strip submenu.** Rows in the taskbar (1, 2 or 3), text size (Small, Default, Large, Larger) and opacity
   (100, 92, 80, 70, 60 %). Changes apply at once.
5. **Version line and Check for updates.** A greyed line with the version, and a check against the latest GitHub release.
6. **Copy all prices.** Puts the whole board on the clipboard as tab-separated text.
7. **Save failures.** When settings cannot be written, the menu shows a greyed line saying so.

## How to use each feature (from the tray menu)

- **Start with Windows:** right-click the tray icon, then tick *Start with Windows*. The tick is read from the
  registry each time the menu opens, so it also reflects changes made elsewhere. If the registry write fails,
  an error box appears.
- **Hotkey:** *Hotkey* submenu, then choose *Off*, one of the four presets (`Ctrl+Alt+M`, `Ctrl+Alt+T`,
  `Ctrl+Shift+F12`, `Ctrl+Alt+Space`), or a combination that is set in the config file (shown as its own entry).
  The hotkey toggles the panel the same way a click on the strip does. Holding the keys down does not repeat it.
  If Windows refuses the combination, the entry shows *(in use by another app)*; if the text cannot be read as a
  hotkey, it shows *(not a valid hotkey)*. Clicking the selected custom entry tries again.
- **Refresh now:** the *Refresh now* entry. Chart rows with no data are requested at once. The backoff after a
  failing source is not reset, so a source that keeps failing still backs off.
- **Strip:** *Strip* submenu. *Rows in the taskbar* is greyed out unless the strip is docked to the taskbar,
  because only the taskbar grid uses it. *Text size* sets the taskbar and the floating size together.
- **Check for updates:** the *Check for updates* entry. The entry reads *Checking...* while the request runs,
  and a second click is ignored until it finishes. The result is a message box:
  - up to date: "MH Ticker <version> is the latest version."
  - newer release: "Version <version> is available. You have <version>. Open the download page?" Yes opens
    https://github.com/mariyaholic/mh-ticker/releases/latest in your browser. Nothing else from the answer is opened.
  - failure: "Could not check for updates (<reason>). Try again later." The reason is one of `network`,
    `HTTP <code>`, `too large`, `unreadable answer`, `could not start`, or `no answer`.
- **Copy all prices:** the *Copy all prices* entry. One line per symbol: label, price, change, separated by tabs. A stale price gets a fourth field, `stale`.
  A symbol with no quote shows `--` for both.
- **Save failures:** the line *Settings could not be saved (changes last until you quit)* appears under the status
  line while the last save failed. It clears itself after a later save succeeds.

## Config fields added

| Field | Type | Default | Notes |
|---|---|---|---|
| `hotkey` | string or null | `null` (no hotkey) | Text in the form `Ctrl+Alt+M`. Old config files without it load as `null`. |

That is the only field added to the config file. *Start with Windows* is stored in the registry, not the config.
The save-failure flag is in memory only and is never written. The strip settings reuse the existing
`dock_rows`, `dock_font_pt`, `font_pt` and `opacity` fields.

A hotkey string grammar: zero or more of `Ctrl`, `Alt`, `Shift`, `Win`, then exactly one key, joined by `+`.
Keys are `A`-`Z`, `0`-`9`, `F1`-`F24`, `Space`, `Home`, `End`, `Insert`, `Delete`, `PageUp`, `PageDown`.
Case and spaces around parts do not matter. At least one of Ctrl, Alt or Win is required.

## The one new network request

- **When:** only when you click *Check for updates*. Nothing is sent at startup or in the background.
- **Where:** `GET https://api.github.com/repos/mariyaholic/mh-ticker/releases/latest`.
- **What is sent:** the request line and headers only. `Accept: application/vnd.github+json`, and the same
  browser-style `User-Agent` string the price requests already use. No body, no cookies, no config, no symbols,
  no version number in the request itself.
- **What is read back:** at most 256 KiB, with a 10 second timeout and no redirects. Only the `tag_name` field
  is read. The tag must be at most 64 bytes with no control characters. It is shown in the message box after
  removing control characters and cutting it to 40 characters.
- **What is not done with the answer:** nothing from the response is opened, and no link from it is followed.
  The download page is a fixed address.

## Decisions

From the builder's hand-off:

- `hotkey::PRESETS`, `preset_index`, `Combo { mods, vk }` (no `MOD_NOREPEAT` inside; `register_hotkey` adds it),
  the `MOD_*` constants and `WM_HOTKEY`.
- The Hotkey menu offers Off, the four presets, and a custom entry (menu ID 5415) when the configured text is not
  a preset.
- The hotkey toggles by the current mode only: strip expands, panel collapses. It works when the strip is hidden,
  because expand shows the window.
- `update::Outcome` is `UpToDate`, `Newer(version)` (the canonical numbers only, `v1.9.0-rc1+x` is `1.9.0`) or `Failed(text)`; `update::decide` turns the body into one.
  `source::get_release` makes the GET, with a fixed set of error texts.
- A failed thread spawn posts the failure itself, so the update flag is always cleared.
- The newer version in the message is `update::canonical(tag)`: digits and dots only (the sanitising in `on_update` stays as a second line of defence). Nothing else from the response is shown.
- A save failure shows as its own greyed line. The link status is kept, not replaced.
- The version line reads `<profile title> <CARGO_PKG_VERSION>`. The version is still 1.7.1 here; the 1.8.0 bump
  belongs to another change.
- *Rows in the taskbar* is greyed unless the strip is on the taskbar. The text steps are named Small, Default,
  Large and Larger, and each sets both font sizes. Ties in the nearest-step helpers go to the lower index.
- *Refresh now* only bumps a counter. The failure backoff is not reset.
- Timer 6 and `WM_APP + 10` are reserved and unused.
- `Start with Windows` shows an error box if the registry write fails. There is no config copy of the setting.

Added by the finisher:

- **Grammar edges.** A key must come after all modifiers, and nothing may follow the key. A modifier may appear
  only once. A leading zero is refused in function keys (`Ctrl+F01`). `Shift+Win+M` is accepted, because Win
  satisfies the modifier rule.
- **Named keys.** The grammar lists seven named keys. The hand-off's test note says six; all seven are tested.
- **Canonical spelling.** `label` orders modifiers Ctrl, Alt, Shift, Win. Every preset is stored in that spelling (a test checks `label(parse(p)) == p`), so the menu and the status line read the same.
- **Control characters in a tag** are checked before trimming, so a tag ending in a newline is refused rather
  than tidied.
- **Versions.** Leading zeros are the same number (`1.08` equals `1.8`). An empty suffix (`1.8.0-`) counts as a
  pre-release. A `+build` suffix never makes a version newer or older.
- **Copy all prices** writes `+0.00%` for a zero change, using the same rule as the panel.
- **Strip steps.** The helpers pick the nearest step in each list. Ties go to the lower index, which for opacity
  is the more opaque step.
- **Registry test.** The round trip uses a throwaway value name (`MH_Ticker_Test_<pid>`) and removes it on exit,
  even when an assertion fails.
- **Save flag.** Only `save_to` and `save_checked` record the outcome. `load_from` goes through `save_to`, so a
  read-only settings folder at startup also shows the save-failed line. The save-flag test is race-free: no
  other test drives a successful save.

## Concerns for the reviewer (left as built, not changed)

1. **Resolved in review:** stale cells are marked with a fourth `stale` field.
2. **A non-finite price prints as `NaN` or `inf`.** `board_text` and `fmt_price` do not guard against it. The
   quote code should keep this from happening, but nothing here checks.
3. **Resolved in review:** the update message shows only `update::canonical(tag)`.
4. **Resolved in review:** the shell-reserved `Win+Shift+M` preset was replaced by `Ctrl+Alt+Space`.
5. **The update request uses the browser-style User-Agent.** That is the string the price requests already use.
   Reviewers may prefer an app-specific one for GitHub's API.

## Unverified

Nothing was clicked on a real Windows desktop. What was checked and how:

- **Run under Wine, with unit tests:** hotkey parse and label (including edge cases), version comparison, the
  release JSON reader, the update decision and its safety test, `board_text`, the strip-step helpers, the
  autostart command quoting and same-command rule, the save-failed flag, the config default, and the
  registry round trip under a throwaway name. Wine's registry is not Windows, so the round trip shows the code
  path works, not that Windows behaves the same.
- **Compiled and tested on Linux without Windows crates:** `hotkey.rs` and `update.rs` pass their 12 tests on the
  host toolchain, which shows they are portable.
- **Stills:** all 36 theme stills are identical to the baseline. The new menu entries are not in the stills.

Reviewed by code only (not run anywhere):

- `RegisterHotKey` actually registering, firing, and being refused by another app.
- `WM_HOTKEY` toggling the panel when the strip is hidden or docked.
- *Start with Windows* taking effect at sign-in (the `Run` key), and the tick following changes made in
  Task Manager's Startup tab.
- The menu look: the checkmarks and radio dots, greyed lines, and the submenu layout.
- The live GitHub request, its timeout and size cap, and the message boxes' wording and buttons.
- *Open the download page* opening the fixed address.
- The strip rows, text size and opacity applying live, and the placement that keeps rows greyed on a floating strip.
- *Refresh now* bringing new chart bars in at once on the chart thread.
- The save-failed line appearing on a read-only folder and clearing after a later save.


## Review changes

- `Feed::wait(d, acted)` takes the `kick` value the caller last acted on, read before its request (quote loop) or before its fetch (chart loop, `seen_kick`), so a kick during a request ends the next wait at once.
- Stale cells in *Copy all prices* carry a fourth field, `stale`.
